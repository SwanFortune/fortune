# Releasing

The procedure existed before this file did — spread across the headers of
`build.sh`, `tests/run_all.sh`, `tests/smoke_export.sh` and `autoload/Version.gd`,
each of which explains its own part and none of which says what order they go
in. This is the order.

Nothing here is new machinery. Every step is a command that already worked; the
point is that they are one list rather than four half-memories.

## Before anything

```
cd godot
tests/run_all.sh
```

Green, all twenty files. Note the `PARLOUR_SEED` it prints — if a later step
goes wrong it is worth knowing which evening the suite played.

CI has already run this on the commit you are about to release, but run it
locally anyway: CI runs on a clean Ubuntu image, and you are shipping from
whatever this machine is.

## 1. Decide the number

`autoload/Version.gd` holds it, and it is the ONLY place it is written down.
`data/base/mod.json` carries the content pack's version and
`tests/test_dead_content.gd` fails if the two disagree, so bump both together.

- **PATCH** — something is fixed and the game is the same game.
- **MINOR** — the game changed for the player: a screen, a rule, a number in
  `data/base/`, a new language.
- **MAJOR** — not yet. It is 0.x until the content is finished; see
  `docs/PORTING_NOTES.md` for what "finished" means here.

A build carries more than the number: `build.sh` writes the commit, the branch,
whether the tree was dirty and the date into `build_stamp.cfg`, and the credits
screen prints them. That is what tells two builds of "0.2.0" apart — and it
exists because a binary sat in `build/` for a day and fifty-four commits, and
the obvious reading of what it showed was that the export was broken rather than
old.

**So: commit the version bump before building.** A stamp that says `dirty` is a
build nobody can trace back to a state of the repository.

## 2. Build all three

```
./build.sh
```

Linux, Windows and macOS, in one go, each checked for existence and a plausible
size — `build.sh` does not trust the exporter's exit code, because Godot reports
some export failures through an `ERROR` line and a zero exit. That is not
hypothetical: the macOS preset failed for months on a disabled texture format
and nothing said so, because nothing ran it.

Artefacts land in `build/`, which is gitignored. They are not committed; they
are uploaded.

## 3. Play the one you can

```
tests/smoke_export.sh --no-build
```

This is the only thing in the repository that tests the artefact a player is
handed rather than the source tree: resources packed, `godot/tests/` filtered
out, the main scene actually booted. It starts the binary, walks five screens
with real keystrokes and lays a card, and asserts that **every step changed the
screen** — a key that reaches nothing leaves the frame identical, which is what
a scene that failed to load looks like.

Only the Linux build can be driven here, and by CI. Windows and macOS are built
but not played: **someone has to open them by hand at least once per release.**
That gap is real and this file will not pretend otherwise.

## 4. Look at it in the language you are not thinking in

```
xvfb-run -a godot --path . -s tests/screenshot.gd -- read /tmp/fr.png 1.2 fr
```

The locale test proves every string has a translation. It cannot prove the
translation fits the box it is drawn in, and French runs longer than English
almost everywhere. Two or three screens is enough to catch a clipped line.

## 5. Tag it

```
git tag -a v0.2.0 -m "..." && git push --tags
```

The tag is what a bug report will be matched against, and the stamp in the build
carries the commit the tag points at.

## 6. Steam

`docs/STEAM_RELEASE.md` is the checklist for everything that needs a Steamworks
account, an App ID or a signing identity — none of which can be done from this
repository. `docs/STEAM_WORKSHOP.md` covers subscribed content.

Nothing in this file depends on any of that: the game builds, plays and ships
as three binaries without Steam existing.

## What is still missing from this procedure

Written down rather than left to be rediscovered:

- **Nobody has run the Windows or macOS builds.** They export and they are the
  right size. That is all anyone knows about them.
- **The art and the sound are placeholders.** Every card face, portrait and
  sound in a build made today is generated by the project itself and meant to be
  replaced — see `docs/ART_GUIDE.md` and `docs/SOUND_GUIDE.md`. The credits
  screen says so out loud, which is the right behaviour for now and the wrong
  thing to ship.
- **There is no changelog.** The commit messages carry the reasoning, which is
  better than a changelog for the people working on it and useless to a player.
